# 自定义工作流

从侧栏「自定义工作流」新建，在本机保存后复用。原有自动规划项目继续使用原来的入口。

## 编辑与触发

1. 新建并命名工作流，选择点击、拖动、提示词触发器。
2. 在「规划输入」添加输入 1、输入 2 等，命名用途并选择文件、视频、音频、图片或文件夹。再添加工具调用、Skill、条件分支或集成与输出节点；在节点设置中选择输入和参数名，点击「绑定输入」。自然语言规划会同时生成输入清单与节点，并保留已声明的输入。生成阶段不执行调用。
3. 选择箭头的起点、终点和条件后连接；点击箭头列表项可删除连线。普通节点使用「完成后」，条件节点使用「是 / 否」。拖动节点标题栏调整位置；聚焦节点按钮后可用方向键移动。
4. 保存后，点击卡片「执行」或拖动卡片到顶部「执行」，进入独立的「执行 · 新需求」页。填写本次任务和输入后点击「开始执行」。也可输入 `用资料整理工作流完成提取这份文档的摘要`，同样先打开新需求表单。每次执行生成独立运行记录；「再次执行 · 新需求」清空上次任务和临时输入，仅带入模板明确配置的默认路径。历史记录保留原输入、日志和产物，不覆盖。

目前执行有向无环图；循环会在保存时被拒绝。独立根节点依次执行，汇入节点等待上游终结；至少一条上游路径激活时继续。条件未命中的分支标记为跳过。失败即停止，不自动重试外部副作用。同一个工作流不能并发运行，避免共享变量竞争。

只读转写分析或语义匹配失败后，运行记录提供「从失败步骤继续」。继续前重新检查所有输入路径，使用原运行的工作流、输入和工作目录快照，跳过已完成和已跳过节点，保留失败记录及恢复时间。它延续同一次需求；「再次执行 · 新需求」仍创建独立运行。普通工具、输出和打包 Skill 的失败不提供此入口，避免重放已发生的写入操作。

Codex 分析与匹配节点使用 `turn/start.outputSchema` 约束最终 JSON，分析请求仅包含该节点所需转写，避免重复发送整份运行状态。兼容返回只允许修复单个可定位的内部闭合符缺失，原始文本与修复位置保留在日志；截断文本、缺失值、错误来源索引和响应 ID 不会被猜测补全。解析错误报告准确字节数和语法原因。候选文字与时间范围仍由服务端按原转写来源索引重新计算。

## 通用输入约定

工作流 `inputs` 保存 `{key, label, type}` 清单，最多 32 项，全部为必需项。名称可改，稳定标识如 `input1` 用于参数 `{{input.input1}}`。保存会拒绝重复标识、不合法类型以及未声明的输入引用（包括 Skill 内部）；删除输入前必须解除节点引用。复制节点携带其输入声明，冲突时明确提示；复制工作流保留输入结构，但不复制本次路径。Skill 打包、撤销和导出保留输入要求。

执行表单由输入清单生成。文件上传流式保存到本机 `workflow-inputs/`，支持文档、表格、图片等任意普通文件；文件夹及超过 2 GiB 的文件填写本机绝对路径。`POST /workflows/:id/preflight` 逐项返回路径是否存在、当前服务是否可读、文件/文件夹类型及媒体扩展名是否匹配。检查使用真实路径，拒绝相对路径、网址、失效链接和不可读取的文件。没有输入的纯文字工作流仍可执行，`input.goal` 仅作为任务文字；旧媒体流程引用的 `input.goal` 自动兼容为文件输入。

运行请求统一使用 `{goal, inputs: {input1: "/完整路径", input2: "/另一路径"}, trigger}`。点击、拖动、提示词和直接 API 调用共用服务端检查，任一输入有问题都不创建运行或调用工具；提示词缺输入会打开补齐表单。检查按钮仅报告当前状态，真正启动时再次检查，且每次工具调用前重新检查全部输入；运行中输入丢失会停止后续工具，保留已有结果。运行快照保存当次解析后的真实路径。工作流间的临时路径按工作流隔离，避免串用素材。

## 复制、剪切与删除

- 画布中选择一个或多个节点后，可复制、剪切、粘贴或删除。支持 `⌘/Ctrl+C`、`⌘/Ctrl+X`、`⌘/Ctrl+V` 以及 `Delete` / `Backspace`；在输入框内仍保留系统原有快捷键。
- 复制节点会带上选区内部的箭头；粘贴时创建新节点 ID，并同步改写选区内部的 `{{outputs.节点ID}}` 引用。指向选区外节点的引用保持不变。
- 「复制工作流」立即创建一个已保存副本，并自动生成不重复的名称。存在未保存修改时会要求先保存或重新载入，避免复制到不明确的状态。
- 「删除工作流」需要二次确认，并在数据库中软删除定义。历史运行及其状态、产物和模型记录继续保留；正在执行的工作流不能删除。

### 本机媒体转写

双视频插入任务同样使用通用输入清单：新规划默认声明 `input1`（素材视频）和 `input2`（主视频），已有命名输入会被保留。两段视频各自转写和语义分析，`agent_media_match` 仅返回候选索引，服务端用真实候选计算插入时间；`local_media_compose` 使用 AVFoundation 逐段保留主视频，在指定句末插入素材，统一画幅并保留各片段音轨，导出 MP4。缺少第二个视频、没有匹配或成片文件/轨道/时长验收失败时不会标记完成。

运行结果顶部显示「下载成品视频（MP4）」，并列出可下载的中间视频、转写和插入清单。下载仅允许访问本次运行目录内已登记的文件，拒绝路径越界和符号链接逃逸。旧版将双视频需求误生成为单视频分析/切片的记录会显示未交付警告；旧片段仍可下载。各转写和切片节点使用独立目录，避免同名文件覆盖。

执行媒体工作流：选中工作流，在顶部各输入框分别选择文件或填写路径，点击「检查输入路径」或直接「开始执行」。每项输入都必须通过服务端检查。旧版 `workflow-media/` 上传路径继续可读，新上传统一存到 `workflow-inputs/`。

可将视频 / 音频拖到执行区导入。执行工作流时，拖动左侧整张卡片或编辑器「拖动整个工作流」手柄到顶部「执行」或执行区；画布节点拖动只调整布局。当前草稿有修改时，启动前先保存。点击执行同样可通过键盘完成。

macOS 26 或更高版本可使用 `local_media_transcribe`。点击「添加转写节点」时会选择或创建一个媒体文件输入；也可在节点设置中重新绑定其他输入。

该工具使用 macOS Speech 的本机模型。视频先由系统 `avconvert` 提取音轨，不依赖 ffmpeg、Whisper 或第三方转写服务，媒体内容不会上传。首次使用某种语言时，macOS 可能联网下载语言资源。转写文本及带时间信息的片段写入 `workflow-runs/<运行 ID>/`，同时登记为中间产物。

自然语言生成的节点不得保存 `workdir`、`loopcanvas-readonly-mode-*` 临时目录或未定义的 `{{globals.*}}`；服务端会拒绝这类不可移植草稿并在生成控件下显示原因。

如果已保存工作流中存在早期生成的 `ffprobe` / `ffmpeg` / Whisper 节点，并同时引用 `{{globals.inputVideoPath}}` 或临时只读目录，界面会显示「替换旧转写节点」。替换保留节点 ID、坐标和连线，只更新工具及参数，并先作为未保存草稿供检查。

媒体类自然语言描述会采用确定性编排，不再要求规划模型自行猜测工具是否存在：

1. `local_media_transcribe` 在本机转写并输出真实时间片段。
2. `agent_transcript_analyze` 只根据转写来源索引识别包袱、捧哏、金句或其他语义候选，生成关键词、评分及理由。服务端会用原始片段重新计算文字和时间范围，模型不能改写原文或伪造时间码。
3. `local_media_clip` 使用 macOS `avconvert` 按候选时间码切出视频或音频，写入片段清单。

生成的工具链作为新草稿节点追加，保留既有图和明确的输入绑定；不因工具名称相同而合并引用不同素材的节点。

## Codex 工具同步

工具目录会合并 LoopCanvas 内建工具与当前 Codex App Server 的实际能力：

- Codex 核心工具，如本机命令、文件补丁、网页检索、图像读取和隔离浏览器验收。
- `mcpServerStatus/list` 返回的全部 MCP 工具，包括工具名称、参数概要、认证状态和服务命名空间。
- 已连接 App 的公开工具摘要；若 App 工具已由 Codex MCP 服务提供，则以 MCP 的真实工具定义为准。

界面显示同步数量、来源和可用状态，并可点「刷新工具」强制重新读取。自然语言生成器只能使用当前目录中 `available=true` 的精确名称；MCP/App 的服务绑定由后端写入节点，不能由提示词伪造。同步只复制能力描述，实际运行仍使用 Codex 当前的登录状态、沙箱、网络和审批边界。

## Skills

在画布空白处拖动框选，或用复选框多选至少两个连续、无分支的工具调用。输入 Skill 名称后「合成为 Skill」，会在一个数据库事务中保存 Skill 并替换选中节点、重接外部箭头。

「撤销合成」恢复原节点和箭头，同时撤销新 Skill。之后若已编辑工作流，或其他工作流已引用该 Skill，不允许覆盖这些后续改动。历史运行保留自己的 Skill 快照。

Skill 节点可选择库中的 Skill，也能「查找本机 Skill」并导入当前内容的快照。库中 Skill 同时显示在「能力 → Skills」，可以导出 `SKILL.md`。导入的 Skill 由 Agent 按其说明执行；合成的 Skill 则由调度器逐条展开原工具调用。

## 状态与数据

- `globals`：同一工作流跨运行共享，首次由初始变量创建，后续由 Agent 的状态补丁更新或删除。
- `context`、`messages`、`outputs`、`artifacts`：每次运行独立，保存上下文、历史消息、节点输出与中间产物。
- 参数引用：`{{input.goal}}`、`{{globals.key}}`、`{{outputs.节点ID}}`；整值引用保留原始 JSON 类型，嵌入字符串时转换为文本。缺失变量明确失败。
- 条件支持等于、不等于、存在、包含。条件路径只读取数据，不执行表达式或代码。
- 每一步保留开始 / 结束时间、执行状态、运行时事件、返回结果、证据、公开模型输出与用量事件。不会要求模型返回隐藏思维过程。

每个节点完成后，状态与共享变量原子持久化。服务重启后，未完成运行标记为「已中断」，不自动重放；停止时保留已完成记录。可在「运行记录」查看数据、日志和历史运行。

## 本机存储与将来的同步

数据库为 LoopCanvas 数据目录中的 `workflows.sqlite`，与原有 `state.json` 并列，文件权限为 0600。运行文件写到配置的工作目录下 `workflow-runs/<运行 ID>/`。数据库中保存工作流、Skill、运行快照、模型记录和共享变量；备份时应同时保留数据库与运行文件。

工作流使用稳定 UUID、schemaVersion、revision、createdAt、updatedAt、ownerId 字段；保存检查 revision，拒绝旧窗口覆盖新版本。当前 ownerId 为空，仅本机存储；账号、网络同步、冲突合并尚未实现。

除 `local_media_transcribe` 外，运行通过现有 dsh / Codex 适配器及其权限边界，集成能力取决于该运行时实际配置的工具。内建转写节点由 LoopCanvas 直接执行，不需要 Agent 侧出现同名工具。
