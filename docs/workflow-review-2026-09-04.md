# Workflow Web 整体审查与修复 · 2026-09-04

## 结论

“新窗口不保存上下文”是有源码和实际请求证据支持的问题，但不是唯一原因。当前产品并非把 Codex 桌面会话原样嵌入网页，而是自建了临时会话、角色路由、交付协议、审核、状态调度和预览层。这些层既会遗漏信息，也可能把正常的验证失败误显示成调用崩溃。

本轮已集中修复执行主链和用户指出的界面问题，并提取共同逻辑；没有重写整个仓库，也没有删除仍用于旧项目兼容的路径。接手时工作区已有大量未提交修改，本轮保留了这些内容。只读检查了既有项目和对话记录；没有重跑真实项目、变更其授权或修改其文件。

## 真实失败证据

检查项目：`1224627b-ff21-4bf9-8902-c2c867d4c82a`（环保演示）。本机记录位于 `~/Library/Application Support/LoopCanvasWeb/conversations/<项目ID>/`。以下时间使用记录文件中的 UTC 时间。

1. `record-2026-09-04T03-58-34.146Z-0cd77e65-2267-4e0d-a5f5-f00b83fe04cb.json`：产物校验把 IPCC 的 HTTPS 引用链接报告为未授权远程资源。工作区接手时已存在区分普通引用与执行依赖的修复，本轮保留并通过回归验证；不是 Codex 本身不会制作。
2. `record-2026-09-04T09-07-09.747Z-42689c33-412c-4b98-8e62-7d95069090fe.json`：界面报“Agent 返回 failure，但没有提供具体错误”，原始回复却明确写了已核验 8 页、第 3 页有孤立标点，并返回 `verificationPassed: false`、阻断问题和证据。根因是解析层只查顶层 `error`，没有处理结构化的负面验证结果。
3. 同一次验证请求只包含直接上游制作节点，遗漏更早的“只交本地 PPTX”用户选择。模型又收到最初 Google Slides 目标和关于登录问题的摘要。实际回复提到 Google Drive `USER_NOT_LOGGED_IN` 与项目规则禁止浏览器，这些约束并不能靠重试消除。

因此，不能据此断言“每一次失败都由上下文造成”，但至少可确认：信息传递缺口、错误分类、权限/连接能力差异都真实存在。

## 发现与修复

| 影响 | 原因 | 本轮处理 |
| --- | --- | --- |
| 后续步骤忘记格式、用户选择 | 每次 `thread/start` 且 `ephemeral: true`；主要传递直接依赖和摘要；审核收到的上下文更少 | 新增 `workflow-context.js`，执行、步骤审核、最终审核共用交接契约：原始需求、硬约束、主产物规格、传递依赖中的确认决定、结果证据和流程拓扑 |
| 执行时收到互相矛盾的规则 | 共用提示词混入“只规划”“选择 single”等不属于执行阶段的指令 | 拆分通用、Graph 规划、兼容路由、执行上下文和预览规则；按职责组合 |
| 有详细失败证据却显示未知错误 | 仅查看顶层 `error` | 统一失败原因提取；仅在验证节点具备明确否定结论、证据和阻断问题时保留为负面验证结果；仍不得验收通过 |
| 无法自然返修，或修错分支 | 返修只接受待审核状态；从数组中寻找最近制作节点 | 支持已有失败验证节点；沿真实传递依赖找制作上游，不选无关分支；界面增加明确返修操作 |
| 并行失败后重复执行或成果丢失 | `Promise.all` 提前拒绝，兄弟任务尚未结束就释放执行锁 | 等待同批全部结束，分别提交成功和失败结果；成功兄弟不重新执行；合并重复校验分支 |
| 已生成文件，但审核断线导致重做 | 执行和独立审核共用一次异常出口，未保留完成结果 | 保留已验证的执行产物和审核待办；提供“只重试审核”；审核退回可进入返修；独立审核异常结束后不再一直显示运行中 |
| 状态偶尔回退、异步更新被覆盖 | 状态写入并发、旧响应覆盖新响应、失败回滚替换对象引用 | 序列化状态变更、增加 `stateRevision`；回滚原位恢复对象身份；阻止较旧响应覆盖当前状态 |
| 调试台混入其他项目 | 全局选中状态与异步回调未绑定项目/iframe；还存在写死的示例内容 | 切项目清理调试选择；异步结果核对项目与 iframe；使用当前项目标题和通用说明，删除示例文案 |
| 拖入 reference 清空已写需求 | 参考更新触发整体重绘，输入只在旧 DOM 中 | 提取按项目/字段保存的草稿模块；输入即时保存、重绘前捕获、重绘后恢复；无项目时参考先进入空草稿项目，不替用户编写需求 |
| 预览大量空白或被挤出屏幕 | 固定最小高度、调试栏反向撑大、尺寸元数据被丢弃 | 前后端共用预览尺寸校验；按真实可用空间等比缩小；支持显式产品根边界；不强制放大、不任意裁掉长文档 |
| 刷新或切项目触发新的 Agent 调用 | 浏览恢复与执行推进混用 | 自动恢复显示不再自动发起新执行；明确提交/执行/恢复后仍可连续推进 |
| 中文回复偶发解析异常 | stdout 分块按块直接解码可能截断多字节字符 | 使用流式 UTF-8 解码；不把 commentary 消息当最终回复；删除重复完成事件 |

## 代码整理边界

本轮提取了三个共同模块：

- `web/src/workflow-context.js`：依赖追溯、交接契约和产物上下文。
- `web/public/project-ui-state.js`：状态版本合并、项目输入草稿和预览归属判断。
- `web/public/preview-sizing.js`：前后端复用的尺寸规范与缩放计算。

同时合并了失败原因解析、重复产物校验和输入临时恢复逻辑，删除冲突的规划/执行指令组合、写死的调试示例、重复完成通知与浏览时自动执行分支。保留 DSH、旧连续/分步执行、原生 Swift 和历史 Bridge 数据，因为仍有兼容用途，不能仅因功能相近便安全删除。

UI 调整遵循仓库 `loopcanvas-ui` 技能：优先可持续使用、明确归属、稳定输入和可见反馈，没有增加装饰性动画或新依赖。

## 尚未等同 Codex 桌面端的部分

以下是能力边界，不是本轮已经实现的功能：

1. **客户端工具和审批。** `web/src/codex.js` 对 App Server 发起的客户端请求仍直接停止，使用 `approvalPolicy: never`。尚未实现通用审批、交互式提问、桌面浏览器和动态工具转发。不能用自动同意或扩大权限来假装解决。
2. **会话仍是临时独立会话。** 这次补的是可靠交接，不是共享全部聊天记忆。独立审核和并行分支不能简单共用同一会话。若要延续每个执行分支，需要另行设计持久线程 ID、恢复、版本失效和取消语义。App Server 将线程生命周期和客户端交互明确暴露给集成方，并不自动复制桌面端：[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。
3. **模型配置不完全相同。** 已检查的本机配置开启智能路由；不同角色会使用 Sol、Luna、Terra，不等于全程使用设置里的同一个 Sol high。它可能影响结果一致性，但本次不能将真实失败直接归因于某个模型。
4. **图片与交付类型。** 当前引用主要传递元数据或提取文本，未实现通用图片像素输入；顶层预览协议仍以 HTML、Markdown、文本为主。PPTX 等通过文件列表和预览包装承载，不能据此承诺原生编辑体验。
5. **项目原有规则。** 新生成规则不再笼统禁止隔离的本机浏览器验证，仍保留授权和目录边界。既有项目的 `AGENTS.md`、宪法没有被覆盖；旧禁令与连接未登录状态仍需在项目中明确解决。新代码不会自动回写过去失败记录。
6. **还有未统一的 UI 状态。** 附件暂存仍是全局队列；学习模式部分异步回调仍直接写全局 `learningUI`，快速切换项目/来源时需继续补归属与请求版本校验。此次重点修复的是执行、调试、需求输入和预览，不宣称所有模块已无竞态。
7. **旧产物的尺寸。** 缺少尺寸或产品根标记的任意 HTML 无法可靠推断“哪一块才是交付物”；不会盲目裁切。多页演示入口仍可能包含自身导航/滚动，单一画布协议不能代替完整演示播放器。

推荐后续顺序：先统一学习状态和附件草稿归属，再明确“固定模型/智能路由”体验，最后按真实任务实现审批/工具/图像能力矩阵与端到端恢复。不要先删掉安全边界来追求表面上的全能。
